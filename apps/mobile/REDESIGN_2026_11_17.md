- Login without the redundant app bar, official logo and labeled email/password controls with icons. Recovery, verification and approval retain their existing flows and use the shared presentation.
- Four registration steps: personal information, cascading address, company/vehicle/documents, then security/consent. Original fields/controllers, uploads and final validation remain intact. Step navigation clears keyboard focus, returns to the top and retains values. Birthday uses a native date picker and still sends YYYY-MM-DD. Server errors remain available across steps.
- Personalized dashboard, prominent QR scan action, responsive grid with all seven actual API queue counts and compensation access. Large text switches the narrow grid to one column.
- Short references in queues with complete originals retained in details and requests; store, relevant city, COD and text/icon status chips. Full addresses stay in details. Completed history keeps existing pagination and detail access.
- Collapsible complete shipment history, Philippine-localized timestamps and accurate no-action messaging. Existing authenticated evidence viewing and image zoom are preserved.
- Compact return summaries with expandable original reference, locations, notes, allowed actions, events and private proof. No return action was added or removed.
- Rider peso-symbol formatting with grouped thousands and exact cents. Other existing mobile money formatting is retained. Compensation shows actual earned/paid values and an empty state; COD remains explicitly separate. Profile adds initials and real account status while keeping contacts, vehicle, theme and logout.

The camera, scan validation, token persistence, event UUIDs, confirmation dialogs, request payloads, multipart upload and server permissions remain authoritative and unchanged. No Laravel file, database record or deployment was changed. No device status operation or proof upload was performed during the redesign. Existing unrelated repository changes were preserved.

## Limits and phone acceptance

This is a presentation refresh using existing components, not a pixel-for-pixel reproduction. Document selection retains the original selected/replace controls; an additional document-preview workflow was not added. The scanner retains its existing camera and flashlight control implementation; hardware availability and permission handling still require the physical check. There is no new search, payment operation, profile editing or backend endpoint.

The redesigned APK has not been physically verified. Passing widget tests does not establish WCAG compliance, TalkBack behavior, camera acquisition, live proof uploads or live status changes. The prior connected-device login result applies to the earlier build.

1. Install with `adb install -r apps/mobile/build/app/outputs/flutter-apk/app-release.apk`; open LubosMart Rider. Do not clear app data. Confirm persistent login or normal login.
2. Check Home counts against the website, every queue destination, full reference/details, history, compensation, returns and profile. Review light/dark appearance, large text, landscape and keyboard navigation.
3. Open registration without submitting. Fill personal fields, choose birthday, move through all four steps and back; verify values, cascading address and document selections survive. Cancel to avoid creating a live account.
4. Scan a real assigned waybill and an invalid QR; validate lookup only. Do not confirm pickup or dispatch on prepared parcels #52–53 or #58–59 without approval.
5. On a delivery, select the existing outcome, capture a fresh photo, preview and retake. Stop before confirmation. Approval naming a specific parcel/action is required before an actual upload/status change; prefer a separate legitimate test assignment.
6. Inspect return details and existing private proof. Keep order #30/parcel #31 and deliveries #60–61 unchanged unless the user explicitly approves consuming a scenario.
